## Bug 分析

### 🔴 潜在 Bug 1：`is_bear_market()` 索引偏移与实际不一致

```python
# live_signal.py:144
rolling_ret = (prices.iloc[-1] / prices.iloc[-window - 1]) - 1

# live_signal.py:193 (regime_detail)
rolling_ret = (df["close"].iloc[-1] / df["close"].iloc[-64]) - 1
```

第一处用 `iloc[-64]`（window=63，-63-1=-64），第二处也用 `iloc[-64]`，逻辑一致。
但 `len(df["close"]) >= 64` 的判断应该是 `>= 65`（因为需要 64+1 个数据点来计算 63 天收益率）。

**修复**: `if len(df["close"]) >= window + 2` 或统一复用 `is_bear_market()` 的结果。

---

### 🔴 潜在 Bug 2：`build_signal_json.py` 的 `_parse_model_info()` 版本解析不健壮

```python
# build_signal_json.py:52
exp_id = manifest.get("source_experiment", {}).get("id", "")
version = "v0305"  # default
if "_v" in exp_id:
    version = "v" + exp_id.split("_v")[-1][:4]
```

当 `exp_id = "weekly_bear_v0305_E1_decontam"` 时，`split("_v")[-1]` = `"0305_E1_decontam"`，`[:4]` = `"0305"`，结果正确。
但当 `exp_id` 包含多个 `_v`（如 `exp_v2_variant_v3`）时会解析错误。

**修复**: 直接在 `manifest.json` 中加 `"version"` 字段，不要从实验名推断。

---

### 🟡 潜在 Bug 3：`enrich_llm_analysis.py` 的 K 线 change 计算可能 NaN

```python
# enrich_llm_analysis.py:39-42
"change": float(
    (r["close"] - df["close"].shift(1).loc[idx]) / df["close"].shift(1).loc[idx] * 100
) if idx != df.index[0] else 0.0,
```

每次迭代都重新计算 `df["close"].shift(1)`，且 `tail(7)` 的第一行不一定是 `df.index[0]`，
所以 `idx != df.index[0]` 会为 True，但 `shift(1).loc[idx]` 可能是 NaN（第一行时）。

**修复**: 先计算 `pct_change = df["close"].pct_change() * 100`，再取 `tail(7)`。
