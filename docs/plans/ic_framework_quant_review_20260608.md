## 0. 先说清楚：我们在玩哪个游戏

| 维度 | V1 默认（机构） | 本项目真实诉求 |
|---|---|---|
| 目标 | 最大化风险调整收益 / alpha | 抓 **~4 年周期**的大致高点 / 低点 |
| 精度 | 越精确越好 | **大致**即可（右侧确认够用） |
| 本位 | USD | **币本位**（KPI = 最终攒到更多 BTC） |
| 仓位 | portfolio / vol targeting | 已长期持有，高点减一部分换稳定币、低点接回 |
| 资产 | 跨资产配置 | 单一资产 BTC |
| 成功判据 | Sharpe / Calmar / MaxDD | **轮动后 BTC 数量 > 死拿（HODL）** |

**一句话**: 这不是「在 N 个资产里优化配比」的问题，是「在一条已知有周期的资产上，少数几次大波段，能不能比躺平攒到更多币」的问题。

## 2. 跟「游戏规则」无关的真硬伤（必须修，否则会误导你下注）

下面这几条是**事实层面的数据卫生问题**，无论币本位还是法币本位都站得住，会直接影响你信哪个指标、有多大把握：

### 2.1 日频重叠让命中率「看起来神准」（影响你的把握判断）

`bottoming_indicator_ic.py` 第 84 行起的 headline：

```python
low = df[df["pct"] <= LOW_Q]   # 全部"低估【日】"逐日取 → 重叠
hit = float((low["r"] > 0).mean())   # 命中率在重叠日上算
```

- MVRV-Z 的「358 低估天」去重后**只剩 ~6 段独立低估期**
- 「87% 命中率」本质是「6 个周期故事讲了 358 遍」
- **风险**: 你照着 87% 下注，会以为把握远高于实际。真实你能依赖的只有 ~3-4 轮周期的证据。

> **对你的意义**: 命中率/超额只能用来**给指标排座次**（谁更值得看），
> 不能当「下次也有 87% 概率」的硬承诺。HTML 报告已标注此点，但脚本仍以日频为主口径。

### 2.2 基线不统一 → 指标排名是「苹果比橘子」（影响你信哪个指标）

报告 §2.3 自己写了：基线「按各指标可用样本期分别计算」——
主流链上 ≈+33.8%、宏观 ≈+35.6%、恐惧贪婪 ≈+38.4%、资金费率 ≈+28.9%。

**减数都不一样，却把超额排在同一张图里排名** → 排名不可信。

> **对你的意义**: 你想知道「哪个指标最会抓底」，但现在的排名混入了基线差异。
> 修法：所有指标用**同一个统一基线窗口**（2018-02~2025-12，剔除上线晚的资金费率）算超额，排名才公平。

### 2.3 子样本 IC 不显著是「宿命」，不是 bug（接受它，别硬凑）

低估区非重叠采样后 N<8，t-stat 做不出。这是 BTC 史上仅 3-4 个大底的结构性限制。
**HTML 已诚实承认。** 对你的诉求，这恰恰说明：别指望「统计显著」，要靠**周期逻辑 + 右侧确认**，而不是 t 值。

## 3. 对你的诉求「不适用 / overkill」的批评（V1 错配，本节澄清）

V1 里下面这些重批评，按你的真实诉求**部分失效或属于过度工程（违反 YAGNI）**：

| V1 批评 | 为何对本项目不适用 |
|---|---|
| 「没回答能不能赚钱」评 D（缺 USD Sharpe） | 你的「赚钱」= **币本位累积**，标准是「轮动后币更多吗」，不是 Sharpe |
| Layer 4 Vol Targeting / 信号平滑 | 你一年动几次仓，无需连续仓位优化 |
| Layer 5 成本 / 滑点 / 延迟到机构精度 | 周期级波段，滑点是噪音（仍需粗算手续费，但非机构精度） |
| A1 Block bootstrap / A4 Newey-West | 对 ~6 个事件做 HAC 是大炮打蚊子 |
| A5 多重检验校正（Bonferroni/Deflated Sharpe） | 18×多窗口校正对「定性排座次」是 overkill |
| B1 跨资产 pooling（拉 ETH/SOL） | 项目方已否：ETH/SOL 体量小、样本不足，且你只看 BTC |

> 这些不是「不严谨」，是「为没在考的题做准备」。砍掉它们不降低对你诉求的可信度。

## 4. 币本位重裁决 + 唯一真正该做的下一步

### 4.1 重新打分（用你的尺子）

| 维度 | 评分 | 一句话 |
|---|---|---|
| 周期心智模型 | A | 镜像陷阱 + 右侧确认 + 长周期效应，对「抓大致高低点」是正解 |
| 信号诚实度 | A- | HTML 报告主动招认所有硬伤，诚实文化满分；脚本主口径待收口（§2.1/§2.2） |
| 排名可信度 | B | 命中率被重叠夸大、基线不统一，影响「信哪个指标」 |
| **币本位可交易性** | **未验证** | **还没回答「轮动 vs HODL 谁的币多」——这才是你的真 KPI** |

**综合**: 框架是一台**好用的「周期温度计」**，能告诉你现在大概在周期的哪个温度区。
但「照这个温度轮动，最后到底攒没攒到更多币」——**还没测过**。这是唯一真正的缺口。

### 4.2 真正该做的，只有这两件（其余都是干扰）

| 优先级 | 做什么 | 回答什么问题 | 对应原 roadmap |
|---|---|---|---|
| **P0** | **事件级口径**：把重叠低估日塌缩成 ~6 个独立事件，看每轮周期底**标没标出来、提前/滞后多少天** | 「这指标到底能不能抓到周期底」 | A2 |
| **P0** | **统一基线窗口**（2018-02~2025-12）重算超额排名 | 「该信哪个指标」 | A3 |
| **P1** | **币本位周期轮动回测**：在标记的高点把一部分仓位换稳定币、低点接回，跑 2018→今，对比**最终 BTC 数量 vs HODL** | **「照这个择时，币更多还是更少」——你的真 KPI** | 新增（替代 V1 的 Layer 5 USD 回测） |
| P2 | 顶+底双端整合成「周期研判」双 tab，共享 expanding 分位引擎 | 工程落地 + DRY | C4 |

> **币本位轮动回测要点**（让它对你诚实有用）:
> - KPI = 期末持有 BTC 数量（轮动策略 vs 全程 HODL），单位是**币**不是 USD
> - 简单规则即可：顶部信号触发 → 减 X% 仓换稳定币；底部信号 + 右侧确认 → 用稳定币接回 BTC
> - 必须算进**手续费**（粗略即可，0.1% 量级），但无需机构级滑点模型
> - 必须做**右侧确认**（站上 SMA50 等），避免接飞刀虚高
> - 诚实标注：仅 ~3-4 轮周期，结论是「方向性参考」，不是统计显著的策略保证
