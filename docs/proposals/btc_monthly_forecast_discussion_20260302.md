# BTC 月线级别预测可行性讨论

> **日期**: 2026-03-02
>
> **背景**: 基于 E1 Conservative 生产模型 (日线择时) 和 LevelForecast (L0 GMV 月度预测) 的经验，讨论是否可以建立 BTC 价格月线级别的预测。

---

## 一、两个项目的核心对比

| 维度 | E1 Conservative (当前 BTC) | LevelForecast (GMV) |
|------|--------------------------|---------------------|
| **预测对象** | BTC 日线二分类信号 | L0 部门月度 GMV 绝对值 |
| **预测窗口** | 21天内涨≥4%（是/否） | 12个月点预测 + CI |
| **粒度** | 日线 | 月线 |
| **数据长度** | ~2200天 (6年) | 60个月 (5年) |
| **核心算法** | LightGBM 分类器 | Prophet / TimesFM / ETS |
| **评估方式** | Kappa + PnL回测 | WMAPE + 方向准确率 + CI覆盖 |
| **本质** | 择时信号 (买不买) | 数值预测 (多少钱) |

---

## 二、结论：能做，但要想清楚三个关键问题

### 问题一：BTC 月线预测，到底想预测什么？

LevelForecast 之所以能 WMAPE 7.7%，核心原因是 **GMV 有强季节性 + 确定性趋势**：
- 11月旺季必爆发（Black Friday）
- YoY 增长率相对稳定（30%~41%）
- 业务有惯性，不会突然暴涨暴跌 10 倍

BTC 月线完全不同：
- **无固定季节性**（halving 周期 ≈ 4年，但不严格）
- **波动巨大**（单月 ±30% 常见）
- **外部驱动为主**（宏观、监管、黑天鹅）

核心问题：**预测月度收盘价的绝对值？月度涨跌方向？月度收益率区间？**

| 目标 | 难度 | 可行性 | 参考价值 |
|------|------|--------|----------|
| 月度收盘价绝对值 | 🔴 极难 | 低 | Prophet/TimesFM 对非季节性资产外推不靠谱 |
| 月度涨跌方向 | 🟡 中等 | 中 | 可以做，但准确率 55-60% 就很好了 |
| 月度收益率区间 | 🟢 较可行 | 中高 | 类似 v002-log 的 CI 思路 |
| 月度 regime 判断 | 🟢 较可行 | 高 | 牛/熊/震荡，跟 E1 的 regime 思路一脉相承 |

### 问题二：LevelForecast 的哪些方法论可以借鉴？

#### ✅ 可以借鉴的

1. **多版本竞赛 (v001~v006)** — 同一个问题用 5+ 种算法跑，回测排名选最优。完全适用于 BTC 月线。

2. **输入变换思路** — LevelForecast 最大的发现：TimesFM 直接喂原始数据 WMAPE 19%，YoY 变换后降到 7.6%。基础模型的"世界观"偏保守，BTC 从几百涨到十万的量级变化在其训练集中属于极端少数。变换的本质是 **把数据翻译成模型能理解的语言**。

   BTC 月线可用的变换策略（按优先级排序）：

   | # | 变换 | 公式 | 核心思路 | BTC 适用性 |
   |---|------|------|---------|:---------:|
   | 1 | **Log-return** | `log(P(t)/P(t-1))` | 金融时序黄金标准，天然平稳+对称+信息无损 | ✅ 最高 |
   | 2 | **Log 变换** | `log(1+P)` | v006a 已验证，压缩指数增长尺度，最简单 | ✅ 高 |
   | 3 | **波动率归一化** | `return / rolling_std` | 类似 Sharpe，消除 BTC 特有的波动率聚集效应 | ✅ 高 |
   | 4 | MoM 月环比 | `P(t)/P(t-1)` | 直觉最简单，类似 GMV 的 YoY 思路 | ✅ 中高 |
   | 5 | 百分位排名 | `percentile_rank(P, window)` | 转为 [0,1]，模型预测"当前处于历史什么位置" | ✅ 高 |
   | 6 | Z-score | `(P-μ)/σ` (rolling) | 滚动窗口标准化，模型看到的永远在 [-3,3] | 🟡 中 |
   | 7 | Halving 周期对齐 | `P(t)/P(t-48)` | BTC 版"YoY"，用 ~4 年周期代替 12 个月 | 🟡 有趣但数据点少 |
   | 8 | STL 分解残差 | `residual = P - trend` | 让模型只预测去趋势后的残差 | 🟡 BTC 无明确季节项 |

   **建议优先试 Top 3**: Log-return → Log 变换 → 波动率归一化，跟 LevelForecast 一样做变换策略竞赛。

3. **CI 区间独立估计** — v002 给点预测、v002-log 给 CI，取长补短。BTC 月线预测更需要 CI（不确定性太大），可以用同样的组合策略。

4. **Holdout 验证设计** — 3个月 holdout，先证明回测能力再做正式预测。BTC 也应该用类似的 expanding window 回测。

5. **多模型交叉验证** — LevelForecast 用 TimesFM / Prophet / ETS 三角验证。BTC 月线同样可以用多个大模型（TimesFM、Chronos、Moirai、Lag-Llama 等）互相交叉验证，用模型集成代替人工判断。

6. **LLM 辅助分析** — 用 LLM（如 Gemini）对月度宏观事件、链上数据、市场情绪做结构化摘要，作为大模型预测的上下文输入或事后解释层，取代传统的人工 Plan 环节。

#### ❌ 不能直接搬的

1. **Prophet logistic growth** — GMV 有 cap（市场天花板），BTC 没有合理的 cap 概念。logistic growth 假设不成立。

2. **乘法季节性** — GMV 有清晰的月度季节性模式，BTC 没有。硬加季节性会引入噪音。

### 问题三：E1 和月线预测怎么配合？

E1 是日线择时，如果再加一个月线级别的方向/regime 判断，可以形成 **多尺度决策框架**：

```
月线模型 (宏观方向)
  │
  ├─ 判定为「牛市月」→ E1 信号权重 ↑，更积极
  ├─ 判定为「熊市月」→ E1 regime 过滤 ↑，更保守
  └─ 判定为「震荡月」→ E1 正常运行
```

这比单独用 E1 的 63 天 rolling return 做 regime 判断更精细。

## 三、推荐路线

1. **目标定义**：不预测绝对价格，而是预测 **月度 regime（牛/熊/震荡）+ 收益率区间**
2. **特征工程**：借鉴 E1 的特征体系（funding rate、FGI、volatility），但聚合到月线级别（月均值、月末值、月内极值）
3. **算法竞赛（以大模型为主）**：
   - TimesFM 2.5 + 变换竞赛（Log-return / Log / 波动率归一化 / MoM，借鉴 v006b 思路）
   - Chronos / Moirai / Lag-Llama 等时序基础模型（zero-shot 对比，同样做变换竞赛）
   - Prophet（作为统计 baseline）
   - LightGBM 分类（跟 E1 一脉相承，预测方向）
4. **LLM 增强层**：用 Gemini 对每月宏观环境（美联储政策、ETF 资金流、链上指标）做结构化摘要，生成定性判断，与定量模型输出融合
5. **评估框架**：方向准确率 + WMAPE + CI 覆盖率（三指标并行，跟 LevelForecast 一样）
6. **与 E1 集成**：月线判断作为 E1 的上层 regime filter

---

## 四、关键风险

1. **数据量瓶颈**：BTC 月线数据只有 ~100 个点（2016 至今），传统 ML 模型样本不足。这正是使用时序基础模型（TimesFM、Chronos 等）的核心理由——它们在海量外部数据上预训练，对小样本场景天然友好。

2. **大模型幻觉风险**：LLM 对宏观事件的定性判断可能包含幻觉或过度自信。必须用定量回测结果约束 LLM 输出，LLM 只做辅助解释，不做最终决策。
