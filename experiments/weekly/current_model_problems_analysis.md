## 二、核心问题：Label 定义与实际场景不匹配

### 2.1 当前 Label 定义 (dip_recovery)

```python
# 当前实现 (V1 版本)
future_low = low.rolling(T).min()  # 包含当天的最低点
dip = (future_low - close) / close
recovery = (future_close - future_low) / future_low

Label = 1 if (dip < -0.05) and (recovery > 0.03) else 0
```

### 2.2 8 点触发场景的真实数据边界

| 时间点 | 可用数据 |
|--------|----------|
| 8:00 AM | 昨日完整 OHLCV + 今日 00:00-08:00 数据 |

### 2.3 核心矛盾

| 问题 | 描述 |
|------|------|
| **信息泄露** | Label 使用了未来 T 天的最低点 (low[t+1] ~ low[t+T]) |
| **训练 vs 预测** | 训练时模型"看到"未来，预测时看不到 |
| **结果** | Kappa = 0.58 可能是虚高，而非真实信号 |

### 2.4 具体例子

假设今天是 2026-02-28 8点:

```
Label[t] 计算需要:
- low[2026-02-28] ~ low[2026-03-20] 的最低点
- close[2026-03-20] 收盘价

但 8 点时，我们知道的是:
- 昨日(2026-02-27)的完整数据
- 今日(2026-02-28) 00:00-08:00 的数据

未来 21 天的数据完全未知！
```
